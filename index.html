Learn the Concepts

Understand the idea first, then use the simulator to observe the same process visually.

What problem does Sliding Window solve?

When two devices communicate, the sender should not have to stop after every frame and wait for an acknowledgement. Waiting after every frame can leave the communication link idle. A sliding window allows several frames to be outstanding at the same time while still controlling how much unacknowledged data can be in transit.

How does it work?

1Create frames — Data is divided into numbered frames such as F0, F1, F2 and F3.
2Open a window — The sender is allowed to transmit only the frames inside its current window.
3Transmit frames — Several frames can be sent before the sender has to wait for all acknowledgements.
4Receive and acknowledge — The receiver accepts frames and sends ACKs according to the selected protocol.
5Slide the window — As frames become acknowledged, the sender moves the window forward and new frames become eligible for transmission.
6Handle loss — If a frame is lost, the sender uses timeout/retransmission behaviour defined by the selected protocol.
7Measure the experiment — FrameFlow records transmissions, losses, retransmissions, ACKs and efficiency so different configurations can be compared.

How does the window move?

Suppose the window size is 3 and the sender starts with F0, F1 and F2 available. After the earliest required acknowledgements arrive, the window moves forward so that new frames can enter it.

1Initial window — The sender may have F0, F1 and F2 in flight.
2ACK arrives — The acknowledged frame no longer needs to occupy a window position.
3Window slides — The base moves forward and a new frame, such as F3, can enter.
4Repeat — The same process continues until all frames are delivered.

What happens when a frame is lost?

GBNGo-Back-N — A timeout at the oldest missing/unacknowledged frame causes that frame and the later outstanding frames to be retransmitted.
SRSelective Repeat — Correctly received out-of-order frames can be buffered, so only the missing frame needs retransmission.

How to use FrameFlow as a learning experiment

  1. Choose a window size and number of frames.
  2. Select Go-Back-N or Selective Repeat.
  3. Use manual loss when you want to deliberately reproduce a particular scenario.
  4. Use Next Step to observe one protocol event at a time, or Auto Play to run continuously.
  5. Try the same experiment with different window sizes or loss conditions.
  6. Compare retransmissions and efficiency in the experiment history and graph.

Go-Back-N vs Selective Repeat

Use the same loss scenario to observe the difference between the two ARQ approaches.

Go-Back-N

When a frame is lost, the sender retransmits the missing frame and subsequent outstanding frames.

F0 ✓ → F1 ✓ → F2 ✕ → F3 → retransmit F2, F3...

Selective Repeat

Correctly received out-of-order frames can be buffered, and only the missing frame is retransmitted.

F0 ✓ → F1 ✓ → F2 ✕ → F3 ✓ → retransmit F2
